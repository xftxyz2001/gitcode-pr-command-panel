# GitCode PR 快捷命令

一个轻量的 Chromium Manifest V3 扩展。在 GitCode Pull Request 页面显示可拖动的悬浮按钮组，点击后通过 GitCode 自身的评论接口立即发送对应机器人命令。

## 默认显示

| 按钮 | 发送内容 |
| --- | --- |
| 编译 | `compile` |
| 查看日志 | `get-log` |
| LGTM | `/lgtm` |
| 批准合入 | `/approve` |

配置页还预置了 [Ascend 社区机器人使用指南](https://gitcode.com/Ascend/infrastructure/blob/master/docs/robot/robot%E4%BD%BF%E7%94%A8%E6%8C%87%E5%8D%97.md) 中适用于 PR 的其他命令，默认不显示。

## 安装

### Chrome

1. 打开 `chrome://extensions/`。
2. 开启右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录 `gitcode-pr-command-panel`。

### Edge

1. 打开 `edge://extensions/`。
2. 开启“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择本目录 `gitcode-pr-command-panel`。

安装后打开以下任一种 GitCode PR 地址即可看到悬浮按钮组：

- `https://gitcode.com/<组织>/<仓库>/pull/<编号>`
- `https://gitcode.com/<组织>/<仓库>/merge_requests/<编号>`

扩展还会复用 GitCode 讨论页自身的轮询结果监控主流水线与文档流水线状态。主流水线识别 `ci-pipeline-passed` / `ci-pipeline-failed`，文档流水线识别 `docs-ci-pipeline-success` / `docs-ci-pipeline-failed`；一次 `add label` 同时包含多个逗号分隔标签时也会逐个识别。对应页面不在当前前台时，系统通知会提示仓库、PR 编号、PR 标题以及通过/失败状态。删除标签或普通评论中仅仅提到这些名称不会触发通知。

如果 `ascend-robot` 直接评论“流水线运行失败”，或者评论“流水线已完成”且结果表中的总流水线行为成功，扩展会先等待90秒；期间出现对应终态标签时以标签为准并取消评论兜底，否则才根据机器人评论发送通知。`运行中`、`已终止运行`以及“不影响流水线执行及 PR 合入”的局部任务文字不会被误判为最终成功或失败。浏览器窗口最小化、切换到其他标签页或其他应用时均可收到通知，但对应 PR 页面需要保持打开，且浏览器和操作系统必须允许通知。

扩展会把每次 discussions 响应记录为轮询心跳。PR 页面进入后台后仍优先等待 GitCode 自己轮询；只有连续15秒没有收到心跳时，扩展才主动补一次请求。页面持续自行轮询或已经回到前台时不会补发请求。后台每5秒检查一次心跳，并使用30秒浏览器闹钟作为 Service Worker 被回收后的恢复兜底。

discussions 接口使用 `sort=desc`，扩展会保存每个 PR 上次响应中 `content.data[0]` 的消息 ID。后续响应只处理该消息之前的新条目，再按时间正序识别流水线标签；同时保存机器人 note 的 `id`、`updated_at` 和正文指纹，以识别同一条流水线评论的原地更新。重复响应不会重复处理，扩大 `per_page` 也不会把更早的历史消息误认为新增。

## 使用与保护措施

- 点击命令按钮后会立即发表评论，不会再次弹出确认框。
- 可在“讨论”“提交”“检查”和“文件改动”任意选项卡中使用。
- 不切换选项卡、不展开评论框，也不覆盖评论草稿。
- 插件直接复用当前 GitCode 登录态调用 PR 评论接口，因此在“提交”“检查”“文件改动”中也能发送。
- 同一个命令发送后的 5 秒内会阻止重复点击，避免重复评论。
- 按住面板标题可拖动位置，点击右上角按钮可收起，点击齿轮可打开配置页；调整窗口尺寸后，面板会自动保持在可视区域内。

## 配置命令

- 勾选或取消勾选命令，决定是否显示在悬浮面板上。
- 可直接修改按钮名称和实际发送内容。
- 支持拖动排序，也支持使用上移、下移按钮调整顺序。
- 支持添加和删除自定义命令。
- 配置保存在浏览器扩展的本地存储中。

## 自定义外观

- 可分别设置命令按钮颜色和悬浮面板背景色；按钮文字、边框、悬停及按下颜色会自动按对比度生成。
- 可选择不超过 2 MB 的本地 PNG、JPEG、WebP、GIF 或 AVIF 图片作为面板背景，并选择覆盖、包含或原始大小居中。
- 背景图片淡化程度可调，数值越高图片越淡、文字越容易看清。设置页会实时预览当前所有已启用命令；新增、删除、改名、启停或排序都会立即反映在预览中，但只有点击“保存配置”后才会同步到所有已打开的 GitCode PR 页面。
- 本地图片以 Data URL 保存在扩展本地存储中，不会上传或请求外部图片地址。图片无效、损坏或旧配置不合法时会自动回退到纯色背景。
- “恢复默认”会同时恢复默认命令和默认外观，并清除背景图片；确认后仍需点击保存。

## 本地测试流水线通知

1. 在悬浮面板点击齿轮打开设置页。
2. 点击设置页底部的“测试流水线通知”。
3. 等待测试页建立历史基线，点击“切走后模拟流水线通过”或“切走后模拟流水线失败”。
4. 切换到其他标签页、最小化浏览器或切到其他应用，由扩展后台主动请求排队的 Mock 结果。

测试页不会访问 GitCode，而是伪造 discussions 响应并依次经过正式的响应解析、前台判断、后台消息和系统通知代码。事件触发时如果测试页仍在前台，通知会按正式逻辑被抑制。

## 注意事项

- `/lgtm`、`/approve` 等命令是否生效取决于当前 GitCode 账号的仓库角色。
- 插件仅注入 GitCode 页面，只申请用于保存命令配置的 `storage` 权限和发送流水线提醒所需的 `notifications` 权限，不申请浏览历史、下载等权限。
